outside QtTune after the session: a script sending ELM commands only
(no DX, no STSN, nothing written to the adapter's memory), each with
its CR, reading to the '>' prompt. Each line is the command sent, then
everything that came back, \r and \n shown as escapes. A second run
gave the same answers. Timings are left out: the script's read loop
set them, not the adapter.
