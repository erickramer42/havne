# ELM327 BENCH session — the VX listening, no bus

**Date:** 2026-10-27, 20:51:02–20:51:32  **Adapter:** OBDX Pro VX (USB, COM4), as an ELM327
**Machine:** the dev machine
**QtTune build:** 8fa2e22
**Evidence:** the connect's wire log and the recording's `events.log`
(Record sessions on), in
[2026-10-27-elm327-bench-3/](2026-10-27-elm327-bench-3/)

## Purpose

BENCH prep #18: passive listening ([ADR-0026](../adr/0026-elm327-transport.md)'s
appendix "passive listening") on a real adapter for the first time. The
VX on USB power, no bus, `elm327://COM4?profile=raw`: no requests, so
the session listens with `AT MA` on the engine ECU's reply ID (`7E8`).
Connected for about 30 s, then disconnected.

## Findings

1. **The setup is a request session's.** `AT Z` answered `OK`, `AT I`
   `ELM327 V2.1`, every contract command `OK` (`AT CRA7E8` the receive
   filter), `STI` `?`, `AT RV` `0.00V`, as in
   [2026-10-27-elm327-bench-2](2026-10-27-elm327-bench-2.md). The
   "Session:" line read "ELM327 adapter (ELM327 V2.1); ISO 15765 at
   500000 baud; profile raw, channel 0x7E8/0x7E0 (rx/tx); battery 0.0 V".
2. **`AT MA` with no bus prints nothing.** No `NO DATA`, no `CAN ERROR`,
   no `BUFFER FULL`: the monitor sat silent until it was stopped.
3. **The 5 s check works.** Five times (at +5.0, +10.0, +15.0, +20.1 and
   +25.1 s) the worker found no line for 5 s and sent one space; each
   time `STOPPED` and the prompt came back within 0.1–0.3 ms, and
   `AT MA` went out again at once. No hard failure, no reopen.
4. **The link went quiet** ("Link: vehicle not responding") 1.3 s after
   the connect, and stayed there with no episode.
5. **The stop at disconnect:** one space, `STOPPED` and the prompt in
   0.2 ms, then the port closed: "the monitor stopped: the session
   closes". The recording ended "0 frames, 0 values".

Not exercised: a space arriving at the prompt (every space crossed a
running monitor), and a monitor that ends unasked.
