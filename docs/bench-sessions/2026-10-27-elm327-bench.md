## Purpose

`elm327://` on a real adapter for the first time, and the Win32 serial
port code's first run (it has no automated test). Goals, in order:

1. The VX gets a serial port over USB (BENCH prep #11)
2. It takes the setup's every command (#12) and gives its readings
   (#13)
3. With no bus at all, its failure word reads as "Requests failing"
   (#15), and an unplugged cable as a fault that recovers (#16)

The evidence is each connect's wire log,
`%TEMP%\ecuio-elm327.<YYYYMMDD-HHMMSS-mmm>.log`: every command, every
line the adapter sent back, and, with **Record sessions** on, every
request and reply with its prompt's time after the request. The
activity log (`events.log` when recording) has the link's states.

## If it fails, suspect

| Symptom | Suspect |
|---|---|
| "COMn: the port is in use by another program" | The vendor app, or a `j2534://` session, holds it |
| "the adapter on COMn didn't answer ATZ within 5 s" | The serial rate: retry with `?serial=115200`. Then a port that isn't the VX's |
| "answered ATZ with '…', not an ELM327 version" | Garbled text: the serial rate, as above. Readable text: the adapter isn't in ELM mode, or another device is on the port |
| Connects, then red "Adapter fault" with the cable in | The port's reads or writes failing: copy the activity log whole |
| The app crashes | Capture the activity log and stop |

## Findings

1. **The port works.** `elm327://COM4` opened the VX's USB serial port
   (`\Device\USBSER000`, Microsoft's `usbser.sys`), wrote, read and
   closed it: the Win32 port code's first run on real hardware.
2. **The VX answers `AT Z` with `OK` alone**, 18.4 ms after it and again
   0.8 ms after the second try, where an ELM327 prints its version.
   The setup refused it (`VENDOR_REFUSED`). Its Command Set Reference
   agrees: `AT Z` "does a full reset", and only `AT I` reports
   `ELM327 v2.1`, "for legacy support". The session stopped there, as
   the sheet says; Phases 3 and 4 didn't run.
3. **The probe** ([vx-probe.txt](2026-10-27-elm327-bench/vx-probe.txt)),
   outside QtTune: `AT I` answers `ELM327 V2.1`, every other contract
   command `OK` (`AT SP 8` too), `STI` `?`, `AT RV` `0.00V` on USB
   power. The reset does reset: the echo it turned off comes back.
4. **With no bus, a request answers `NO DATA`**, not `CAN ERROR`: the
   VX can't tell a missing bus from an ECU that doesn't answer, so the
   link will read quiet ("Vehicle not responding"), not "Requests
   failing".
