# ELM327 BENCH session — the VX's WiFi beside a USB session

**Date:** 2026-10-27, from about 22:28  **Adapter:** OBDX Pro VX: a USB session from the laptop, and WiFi beside it
**Machines:** the laptop (QtTune, `j2534://OBDX Pro - VX`, then `elm327://COM4`, no bus); the dev machine's Wi-Fi list, then the laptop's
**QtTune build:** the laptop's install
**Evidence:** what both screens showed, written down as it happened. No
logs: the laptop's stayed on the laptop, and no machine got far enough
to connect over WiFi.

## Purpose

BENCH prep #20's last item: whether the VX's WiFi works while a program
holds its USB port ([ADR-0026](../adr/0026-elm327-transport.md)'s
appendix "WiFi over TCP"). It started right after
[2026-10-27-elm327-bench-5](2026-10-27-elm327-bench-5.md), whose second
run left the VX's network side hung.

## What happened

| Step | Laptop (USB) | Wi-Fi (the dev machine's list; step 8 the laptop's) |
|---|---|---|
| 1 | J2534 connected: "Requests failing", as every no-bus J2534 session reads | the VX's network not listed |
| 2 | Disconnect, then a wait | still not listed |
| 3 | the VX power-cycled (its USB unplugged and plugged back) | listed again |
| 4 | J2534 connected | still listed |
| 5 | J2534 still connected | joining it: "Can't connect to this network" |
| 6 | Disconnect | the join still failed; then the network was gone, and stayed gone |
| 7 | the VX power-cycled; `elm327://COM4` connected, "Link quiet" | listed |
| 8 | `elm327://COM4` still connected | the laptop joining it: "Can't connect to this network" |

Steps 1 and 2 began with the VX still hung from the session before, so
they show nothing about J2534 by themselves.

## Findings

- **With a session holding the USB port, the VX refused a WiFi join,**
  J2534's binary protocol (step 5) and the ELM command set (step 8)
  alike, though its network was listed. A different machine made each
  join, so neither machine's Wi-Fi explains it.
- **After that, the access point went away** and didn't come back with
  the USB session closed (step 6). Which of the three ended it (the
  J2534 session, its close, or the refused join) these steps can't
  tell; each would need its own run from a power cycle.
- So the VX gives **one link at a time** in practice: power-cycle it
  before using WiFi after USB, as after an unclean leave
  (2026-10-27-elm327-bench-5).
